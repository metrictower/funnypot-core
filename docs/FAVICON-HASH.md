# Persona-coherent favicons (FP-0230)

Aggregate fingerprinters (Shodan `http.favicon.hash`, FOFA `icon_hash`, lonkero
`favicon_hash_scanner`) identify a host's stack by hashing the favicon it serves and matching a
known-product table (Jenkins `81586312`, WordPress `-335242539`, Grafana `999357577`, …). Before
FP-0230 funnypot served no image favicon — `GET /favicon.ico` resolved to nuclei text bundles
(springboot JSON, a Procore login stub), itself an incoherence a fingerprinter can flag, and the
favicon-hash channel emitted nothing corroborating the persona.

FP-0230 serves a real, inert, size-capped favicon whose favicon hash **equals the product the
persona presents**, so the favicon-hash channel corroborates the disguise. Payoff is against
Shodan/Censys-class aggregate fingerprinting and attacker `http.favicon.hash:` dorks — not lonkero
(which does not cross-check coherence).

## The hash (correctness contract)

```
hash = murmurhash3_x86_32( chunk_split(base64_encode(icon_bytes), 76, "\n") , seed = 0 )   # signed int32
```

`chunk_split(base64_encode($b), 76, "\n")` is byte-identical to Python `base64.encodebytes` (a `\n`
every 76 output chars + a trailing `\n`) for every non-empty input — the wrapping is part of the
hashed bytes. Implemented in `src/Support/FaviconHash.php` (**compile/CI/dev-only**; the serve path
only `base64_decode`s the bytes). PHP ints are 64-bit on prod, so every 32-bit multiply routes
through `mul32()`, which masks the high partial to 16 bits **before** the `<<16` shift so no
intermediate reaches `PHP_INT_MAX` and promotes to float. `hash()` asserts `PHP_INT_SIZE >= 8` and
throws on a 32-bit host (a GMP `mul32` fallback is documented) rather than ship a silently-wrong
number.

`tests/Support/FaviconHashTest` pins `FaviconHash::hash` to the scanner reference using an
**independent** C oracle (`scripts/dev/favicon/oracle.c`, a plain `uint32_t` port — not the PHP
split multiply): 94 varied-length vectors + 24 overflow-window vectors selected because the rejected
un-masked-shift `mul32` diverges on them (red-on-bug by construction).

## Provenance: self-generated collision blobs

A favicon hash is a function of exact bytes, so matching a published signature needs either (A) the
vendor's real favicon — its logo/wordmark, trademark-protected and carved out of the code license
even for GPL/AGPL OSS, clearing neither `resources/ALLOWED-LICENSES.txt` nor
`scripts/ci/check-license.sh`; or (B) **self-generated bytes that collide to the same 32-bit value**.
FP-0230 uses (B): a generic self-drawn ring icon (no vendor artwork) with 6 benign trailing bytes
brute-forced (offline, seconds in C — `scripts/dev/favicon/forge.c`) until the hash matches. The
bytes are ours; a 32-bit integer is not copyrightable → clean. The honest catch is the icon does not
*look* like the vendor logo — acceptable for a hash-only threat model (scanners hash, they do not
render or pixel-compare). See `resources/favicons/README.md` for the per-asset forge commands.

## Serving binary bytes (base64-at-rest)

A route template carries an image body as `response.body_b64` (a single-line base64 string; a
`binary: true` marker forces it), which keeps every compiled artifact ASCII-clean under `var_export`.
The compiler stamps `bin => 1` and skips the directive/marker body guards (base64 is opaque ASCII);
the runtime `RouteTemplateEmulator` `base64_decode`s and serves the bytes verbatim (no directive
render, taunt, or token append) with `Content-Type: image/x-icon` and **no charset**;
`ResponseSynthesizer` routes a `bin` bundle to the emulator regardless of style (so it serves even
under MINIMAL), with a null-registry guard (a no-registry host serves no favicon, never fatals). The
fingerprint-safety gate skips `bin` rules (no textual matcher surface).

## Coherence — what ships, what is deferred

- **Within-page coherence (the win).** Each product decoy page's `<link rel="icon" href="X">` points
  at a `bin` favicon route at `X` whose bytes hash to that product. A scanner following the link
  (Shodan does) gets a hash-matching, deterministic icon. Shipped for **Grafana, phpMyAdmin, Jenkins,
  Tomcat**.
- **Neutral bare-root.** `GET /favicon.ico` serves a neutral icon whose hash is not any known-product
  signature — corroborates nothing, contradicts nothing (removes the old JSON/HTML tell).
- **Deferred (residual tell, do not over-claim).** Making the bare-root `/favicon.ico` hash-match the
  `/`-lottery persona needs the global per-attacker family selector deferred in **PERSONA-CAP.md §6**
  (`PersonaSelector::pick` chooses independently per path). A follow-up can couple both once that
  selector exists.

## Adding a product

Forge the asset (`resources/favicons/README.md`), drop a
`templates/route/NNN-<product>-favicon.yaml` binary route, point the product page's
`<link rel="icon">` at it (avoid an `id` that a broad `template_needle` would substring-match — e.g.
the Tomcat favicon id is `route-catalina-favicon`, not `route-tomcat-favicon`), then rebuild:
`compile-routes → merge-routes → build-manifest`.
